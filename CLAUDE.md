# Звонилка

Видеозвонок по ссылке без своих серверов: страница на GitHub Pages, поиск друг друга через публичные MQTT-брокеры, звук и видео — напрямую между участниками по WebRTC. Она же — Mini App в Telegram (бот `@StartNewCallBot`). План — `docs/PLAN.md`, интерфейс и жесты — `docs/UX.md`. С пользователем и в проекте — всё по-русски: интерфейс, документация, комментарии, сообщения коммитов.

## Структура
- `web/` — страница звонка, статическая, без сборки и зависимостей; публикуется как есть.
  - `call.js` — звонок без интерфейса: комната из ссылки, шифрованный сигналинг через MQTT, сетка P2P (на пару — одно соединение с пятью постоянными каналами), микрофон, камера, экран. Наружу — состояние (`me`, `peers`) и события (`on`).
  - `ui.js` — интерфейс: плитки, раскладка, жесты, громкость участников, сообщения, лист, подсказки, режим Telegram.
  - `style.css`, `index.html` (разметка и политика содержимого), `icon.svg` → `icon.png`.
- `node/` — медиа-узел на Zig 0.17.1 (этап 3 плана, раздел «Медиа-узел»): программа `zvonilka-node` входит в комнату как пересылающий участник, и страница строит соединения через неё.
  - `src/node.zig` — комната, пары плеч, пересылка RTP, RTCP и сообщений; `src/leg.zig` — плечо: соединение с одним браузером (ICE, DTLS, ключи SRTP, SCTP).
  - `src/signal.zig`, `mqtt.zig`, `ws.zig` — сигналинг, как у страницы; `stun.zig`, `sdp.zig`, `dtls.zig`, `srtp.zig`, `rtp.zig`, `rtcp.zig`, `sctp.zig` — протоколы, чистая логика над байтами с тестами; `netif.zig`, `room.zig`, `main.zig`.
  - STUN, DTLS, SCTP и MQTT взяты из RDC (`../RDC/src/net/`) и дополнены; дальше живут своей жизнью.
- `tools/serve.mjs` — раздать `web/` на localhost; `tools/call_test.mjs` — живая проверка страницы; `tools/node_test.mjs` — живая проверка узла.
- `bot/bot.mjs` — инлайн-бот без зависимостей: шлёт в чат кнопку «Войти в звонок».
- `.github/workflows/pages.yml` — публикация `web/` на GitHub Pages.
- `app/`, `lib/`, `public/`, `Dockerfile`, `telegram-bot.js`, `package.json` — прежняя версия на Next.js и LiveKit. Не трогать и не удалять без решения пользователя: она может быть развёрнута.

## Команды
- страница локально: `node tools/serve.mjs` → http://localhost:8080 (на localhost камера работает без https)
- проверка: `node tools/call_test.mjs` — три участника в headless Chrome (компьютер, телефон, компьютер), настоящие брокеры, жесты пальцами и мышью; нужна сеть и Chrome (`CHROME=<путь>`, если он не в /Applications)
- снимки экранов: `node tools/call_test.mjs --shots <папка>` — камеры заменяются нарисованными людьми
- синтаксис: `node --input-type=module --check < web/ui.js` (файлы в `web/` — модули ES)
- узел (`ZIG=~/Applications/zig-0.17.1/zig`, из папки `node/`): `"$ZIG" build` → `zig-out/bin/zvonilka-node`; `"$ZIG" build test` — юнит-тесты; `"$ZIG" build -Doptimize=small` — сборка на размер (0,6 МБ); `-Dtarget=x86_64-linux` — под Linux
- запуск узла: `node/zig-out/bin/zvonilka-node <код комнаты или ссылка> [--port N] [--ip A.B.C.D] [--srtp cm|gcm] [--tcp] [--verbose]`; останавливается по Ctrl+C и прощается с комнатой
- проверка узла: `node tools/node_test.mjs` — участники в headless Chrome соединяются только через узел (сначала собрать узел; `--log` — журнал узла на экран; `ZVONILKA_NODE=<путь>` — другой бинарник); `node tools/node_test.mjs --soak cm|gcm` — долгая, минут на двадцать пять: номера пакетов проходят полный круг
- иконка после правки `icon.svg`: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --hide-scrollbars --force-device-scale-factor=1 --window-size=512,512 --screenshot="$PWD/web/icon.png" "file://$PWD/web/icon.svg"`

## Договорённости
- Страница остаётся без сборки и без сторонних библиотек. Единственный чужой скрипт — `telegram-web-app.js`, и грузится он только внутри Telegram.
- Политика содержимого в `index.html` разрешает только свои файлы, скрипт Telegram и два брокера. Новый адрес — значит правка политики. Стили — только в `style.css`; из кода — через `element.style`, без атрибута `style` в разметке.
- Своих серверов нет и не появляется: всё, что нельзя сделать страницей, брокерами и прямым соединением, — в медиа-узел на Zig (этап 3 плана).
- `call.js` не знает про интерфейс, `ui.js` не лезет в соединения: между ними состояние и события.
- Интерфейс меняем по принципам из `docs/UX.md`: минимум кнопок, только знакомые жесты, у жеста всегда есть запасной путь. Новая кнопка или панель — крайний случай.
- Перед тем как сказать «работает» — `node tools/call_test.mjs`; после правок вида — снимки и посмотреть их глазами. Новое поведение — новая проверка в тесте.
- Сообщения комнаты у страницы и узла общие (`web/call.js` и `node/src/signal.zig`, `node/src/node.zig`): меняешь формат в одном месте — меняй в другом и в разделе «Медиа-узел» плана. После правок узла или звезды в `call.js` — `zig build test` и `node tools/node_test.mjs`; `call_test.mjs` при этом тоже должен проходить.
- Zig 0.17.1: API `std` (особенно `std.Io`) сверять с исходниками установленного Zig, а не по памяти; проверенные заметки — `../RDC/docs/zig-0.17-api.md`. В узле нет зависимостей и нет libc на Linux: один статический бинарник.
- Секреты лежат в `.env.local` (ключи LiveKit, токен бота): не печатать, не коммитить, в код не переносить. Странице токен бота не нужен.
- Git: ветка `main`; коммитить только по просьбе, перечисляя пути; сообщения по-русски.
- Итоги и решения дописывать в `docs/PLAN.md` и `docs/UX.md`, а не заводить новые заметки.
